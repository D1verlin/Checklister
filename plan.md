## 1. Архитектура и стек технологий

* **Desktop-оболочка:** **Tauri v2** (Rust + WebView) или **Electron**.
* *Преимущество Tauri:* минимальный вес билда, нативная и быстрая работа с файловой системой и запуск системного плеера без задержек.


* **Frontend:** React / Svelte / Vue + Tailwind (или чистый CSS по токенам скилла).
* **Локальная БД:** **SQLite** (хранение кэша тайтлов, распознанных файлов, статуса просмотра, истории и пользовательских путей).
* **Работа с внешним плеером:** Запуск через системные вызовы (`open` на macOS, `xdg-open` на Linux, `start` / ассоциированное приложение на Windows) либо прямой вызов заданного в настройках бинарника (VLC, MPC-HC, mpv, IINA).

## 2. Модуль сканирования и парсинга (Scanner & Parser)

### 2.1. Алгоритм разбора имен файлов и папок

Для точного сопоставления с базой данных релизные имена (например, `[SubsPlease] Sousou no Frieren - 04 (1080p) [ABCD1234].mkv`) очищаются:

1. **Нормализация строки:** удаление тегов релиз-групп (`[...]`, `(...)`), технических параметров разрешения (`1080p`, `x265`, `HEVC`, `AAC`), хэш-сумм CRC.
2. **Экстрактор серий:** регулярные выражения для извлечения паттернов: `S01E04`, `EP04`, `- 04`, `Episode 04`, `04v2`.
3. **Определение сезона:** если структура вида `Titul/Season 2/ep01.mkv`, имя сезона наследуется из вложенности.

### 2.2. Интеграция с API (Русский + Английский контекст)

* **Русскоязычные данные:** **Shikimori API v2 / GraphQL** (официальные русские названия, локализованные синопсисы, статусы выхода, студии озвучки/дубляжа).
* **Англоязычные и международные данные:** **AniList API (GraphQL)** или **Jikan (MyAnimeList)** (высококачественные вертикальные/горизонтальные постеры, баннеры, японские ромадзи-названия, точный хронометраж и дата выхода новых серий).
* **Fallback-ручной маппинг:** если автопарсинг сомневается (коэффициент совпадения строки < 80%), на карточке выводится кнопка ручного сопоставления (`Редактировать привязку`).

## 3. Функциональные возможности (Что еще внедрить в проект)

Помимо базового просмотра и прогресс-бара, в локальный трекер закладываются:

1. **Отслеживание прогресса просмотра (Watch State):**
* Ручная отметка серий («Просмотрено» / «Не просмотрено») кликом по чекбоксу.
* Опциональный фоновый мониторинг: приложение засекает запуск файла и время возврата фокуса, предлагая инкрементировать счетчик серии.


2. **Умная кнопка «Продолжить просмотр»:**
* Главное действие в библиотеке — кнопка, которая в 1 клик открывает именно следующую непросмотренную серию в очереди.


3. **Статус онгоингов (Airing Schedule):**
* Сравнение количества локальных файлов с общим количеством вышедших серий по API.
* Бейдж: `12 / 12 Завершен` или `08 / 24 Онгоинг (След. серия через 3 дня)`.


4. **Быстрый доступ к папке:**
* Кнопка «Показать в проводнике / Finder» как для всего тайтла, так и для конкретного файла.


5. **Анализ дубликатов и битых путей:**
* Подсветка файлов, если папка была перемещена или удалена с диска.

## 4. UI/UX Спецификация под `dark-monolith-ui`

Так как в проекте ключевую роль играют постеры и баннеры, в соответствии с правилами скилла интерфейс активирует **Glass/Blur режим**:

### 4.1. Сетка библиотеки (Library Grid)

* **Постеры:** вертикальное соотношение `2:3` с радиусом скругления `var(--r-md)` (10px).
* **Glass-карточки:**
* Поверхности под списком и карточками используют `background: rgba(26, 26, 26, 0.75)` с `backdrop-filter: blur(16px)`.
* Никаких односторонних рамок — замкнутый `border: 1px solid rgba(255, 255, 255, 0.08)`.


* **Оверлеи на постерах:**
* Полупрозрачные матовые плашки `rgba(0, 0, 0, 0.75)` с `backdrop-filter: blur(8px)`.
* В правом нижнем углу постера — моноширинный счетчик эпизодов (`04 / 12`).



### 4.2. Элементы управления и прогресс

* **Прогресс-бар:** плоская полоса высотой `4px` (`rgba(255, 255, 255, 0.08)` трек, заливка `#FFFFFF`), без эффектов свечения, без градиентных теней и размытий.
* **Иконки:** исключительно контурные векторные SVG-иконки (Play, Folder, Refresh, Check, Settings, ExternalLink). **Полный запрет на эмодзи.**
* **Статусы:** статические плашки со скруглением `4px–6px` и моноширинным шрифтом:
* `Смотрится` — фон `rgba(255, 255, 255, 0.1)`, текст `#FFFFFF`.
* `Завершено` — фон `rgba(255, 255, 255, 0.05)`, текст `#888888`.
* Никаких пульсирующих точек и анимаций мигания.

## 5. Этапы реализации (Roadmap)

### Этап 1: Backend / Ядро сканера

1. Создание репозитория и конфигурация десктоп-рантайма (Tauri v2 + Rust/Node API).
2. Написание модуля сканирования каталогов:
* Фильтрация медиа-расширений (`.mkv`, `.mp4`, `.avi`).
* Нормализация строки названия папки/файла и выделение номера серии.


3. Интеграция запуска системного плеера по умолчанию через нативный шелл.

### Этап 2: База данных и работа с API

1. Подключение локальной SQLite (схемы: `Anime`, `Episodes`, `WatchHistory`, `ScanDirectories`).
2. Клиент к **Shikimori GraphQL** и **AniList API**:
* Поиск тайтла по очищенному имени.
* Загрузка постера, оригинального и локализованного названия, описания, общего числа эпизодов.
* Кэширование изображений и метаданных локально, чтобы приложение работало офлайн.



### Этап 3: Интерфейс и компоненты (стиль `dark-monolith-ui`)

1. Верстка основного каркаса (боковая панель навигации, шапка с поиском и кнопкой сканирования).
2. Верстка сетки библиотеки с Glass-эффектами поверх постеров.
3. Верстка страницы тайтла:
* Баннер с блюром на заднем плане.
* Монохромный прогресс-бар и счетчики (`--font-mono`).
* Список обнаруженных серий с кнопками запуска во внешнем плеере и отметкой о просмотре.


4. Модальное окно настроек (выбор папок для сканирования, выбор плеера: системный по умолчанию или кастомный путь к `.exe`/бинарнику).

### Этап 4: Тестирование и полировка

1. Проверка распознавания нестандартных форматов имен (аниме с несколькими сезонами в одной папке, спешлы, OVA).
2. Стресс-тест библиотеки на больших коллекциях (100+ тайтлов, 2000+ файлов).
3. Валидация строгого соблюдения дизайн-системы: проверка отсутствия эмодзи, свечений и односторонних рамок.
